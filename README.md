# FileBridge

A personal, self-hosted file-transfer app for moving files between your
Android/iOS phone and any **Linux distribution** (Ubuntu, Fedora, Debian, Arch, AlmaLinux, openSUSE, etc.) over real **SSH/SFTP** — the same
protocol `scp`/`sftp`/FileZilla use, just wrapped in a native mobile UI.

No cloud, no accounts, no commercial backend: your phone talks directly to
your Linux computer's OpenSSH server over your local network (or over the
internet if you port-forward/VPN, entirely up to you).

- Mobile app: Flutter (`FileBridge`), builds for Android now, and for
  iOS once built on a Mac with Xcode.
- Transfer engine: [`dartssh2`](https://pub.dev/packages/dartssh2) — a pure
  Dart SSH2/SFTP client, so there's no native library to compile for either
  platform.
- Server: your existing Linux machine's OpenSSH server. Nothing custom to
  deploy or maintain.

---

## 1. How it works

```mermaid
flowchart LR
  A[Phone: FileBridge app] -- SFTP over SSH port 22 --> B[Linux PC: openssh-server]
  B -- reads/writes --> C[Your files]
```

1. You add a "server" profile in the app: your Linux machine's IP/hostname,
   SSH port, username, and either a password or a private key.
2. The app connects over SFTP and shows a remote file browser.
3. You pick files on your phone to **upload**, or tap files on the server to
   **download**. Transfers run in a background queue with progress bars and
   can be cancelled.
4. The first time you connect to a given host, the app remembers ("trusts")
   its SSH host-key fingerprint. If that fingerprint ever changes
   unexpectedly, the app warns you before connecting (protects against
   spoofed servers).

## 2. One-time setup on Linux (the "server")

1. Install and enable the SSH server (command varies by distro):

   - **Ubuntu / Debian / Linux Mint / Pop!_OS**:
     ```bash
     sudo apt update && sudo apt install openssh-server
     sudo systemctl enable --now ssh
     ```
   - **Fedora / RHEL / CentOS / AlmaLinux / Rocky Linux**:
     ```bash
     sudo dnf install openssh-server
     sudo systemctl enable --now sshd
     ```
   - **Arch Linux / Manjaro**:
     ```bash
     sudo pacman -S openssh
     sudo systemctl enable --now sshd
     ```
   - **openSUSE**:
     ```bash
     sudo zypper install openssh
     sudo systemctl enable --now sshd
     ```

   Check that it is running:
   ```bash
   sudo systemctl status ssh || sudo systemctl status sshd
   ```

2. Find the IP address you'll type into the app:

   ```bash
   ip -4 addr show | grep inet
   ```

   Use the address on your Wi-Fi/Ethernet interface (e.g. `192.168.1.20`),
   not `127.0.0.1` or the `docker0` address.

3. (Recommended) Use a normal, non-root user account for `username` in the
   app — the one you already logged in with.

4. (Optional but recommended) Set up key-based login instead of a password:

   ```bash
   # On your Linux machine, generate a key pair if you don't have one:
   ssh-keygen -t ed25519 -C "filebridge"
   # This creates ~/.ssh/id_ed25519 (private) and ~/.ssh/id_ed25519.pub (public).

   # Authorize the public key for logins:
   cat ~/.ssh/id_ed25519.pub >> ~/.ssh/authorized_keys
   chmod 600 ~/.ssh/authorized_keys
   ```

   Then, in the FileBridge app, choose **Private key** auth and either paste
   the contents of `~/.ssh/id_ed25519` (the private key) or import it as a
   file, so the phone authenticates without a password.

   > Copy the private key to your phone using whatever channel you trust
   > (e.g. `adb push`, a cable, or a temporary encrypted share) — never
   > email it or upload it anywhere public.

5. If you only ever use FileBridge on your home Wi-Fi, no firewall changes are
   needed unless your distro enables a strict firewall (like `firewalld` or `ufw`):
   - **ufw** (Ubuntu/Debian): `sudo ufw allow 22/tcp`
   - **firewalld** (Fedora/RHEL): `sudo firewall-cmd --add-service=ssh --permanent && sudo firewall-cmd --reload`

   If you want to reach your Linux machine from outside your home network, set up a
   VPN (e.g. WireGuard/Tailscale) rather than exposing port 22 directly to the internet.

## 3. Project layout

```
FileBridge/
  lib/
    models/            connection_profile.dart, remote_entry.dart, transfer_task.dart
    services/
      secure_store.dart     encrypted storage for saved servers + trusted host keys
      ssh_service.dart      SSH/SFTP connection, browsing, upload/download
      transfer_manager.dart background transfer queue (max 2 concurrent)
    screens/
      connections_screen.dart      list of saved servers
      edit_connection_screen.dart  add/edit a server (password or key auth)
      session_screen.dart          connects, shows host-key warnings/errors
      files_tab.dart               remote file browser (browse/upload/download/rename/delete/mkdir)
      transfers_tab.dart           live transfer queue with progress + cancel
    theme.dart, utils/formatters.dart
  android/, ios/        native platform projects generated by Flutter
```

Saved server profiles (including passwords/keys) are stored via
`flutter_secure_storage`, which uses the Android Keystore / iOS Keychain —
never plain text on disk.

## 4. Running the app

### Prerequisites (already installed on this machine)

- Flutter SDK 3.44+ (`flutter --version` to confirm)
- Android: Android Studio / `sdkmanager` command-line tools + an emulator or
  a physical phone with USB debugging enabled
- iOS: **requires a Mac with Xcode** — Flutter's iOS build step cannot run on
  Linux. You can still write/edit the Dart code here; you'll need a Mac (or a
  CI service like Codemagic) to produce the actual `.ipa`/simulator build.

### Get dependencies

```bash
cd path/to/FileBridge
flutter pub get
```

### Run on a connected Android device or emulator

```bash
flutter devices        # confirm your device/emulator shows up
flutter run             # hot-reloadable debug run
```

### Build an installable Android APK

```bash
flutter build apk --debug     # fast, larger APK, for testing on your own phone
# or, for a smaller, optimized build:
flutter build apk --release
```

The APK appears at:

```
build/app/outputs/flutter-apk/app-debug.apk      (or app-release.apk)
```

Copy it to your phone (`adb install build/app/outputs/flutter-apk/app-release.apk`,
or transfer the file directly) and install it — you'll need to allow
"install unknown apps" for whichever app you use to open the APK, since this
isn't distributed through the Play Store.

### iOS

On a Mac with Xcode installed:

```bash
cd FileBridge
flutter pub get
open ios/Runner.xcworkspace
```

Select your device/simulator in Xcode and hit Run, or use
`flutter build ios` for a device build (requires an Apple ID / provisioning
profile for a real device — a free personal-team profile is enough for
side-loading onto your own phone via Xcode).

## 5. Using the app

1. Open the app → **Add server** → fill in name, host/IP, port (22 by
   default), username, and choose Password or Private key auth.
2. Tap the server card to connect. On first connect you'll silently trust its
   host key; if it ever changes you'll see a warning screen before the app
   connects.
3. **Files tab**: browse folders, tap a folder to enter it, tap a file to
   download/rename/delete it, use the folder-plus icon to create a new
   remote folder, and the floating upload button to pick one or more files
   from your phone to send to the current remote folder.
4. **Transfers tab**: see all uploads/downloads with progress bars; cancel
   an active transfer or remove a finished one from the list.
5. Downloaded files are saved under an app-specific `FileBridge` folder
   (Android: app-specific external storage, shown in the snackbar after each
   download; iOS: the app's Files/On My iPhone folder, since the app enables
   file sharing).

## 6. Security notes

- Credentials and trusted host-key fingerprints are stored using the OS
  keystore/keychain via `flutter_secure_storage` — never as plain files.
- Host-key verification uses trust-on-first-use (TOFU), the same model SSH
  clients like `ssh`/PuTTY use, with a blocking warning if a trusted host's
  key ever changes.
- Prefer key-based auth over passwords (see step 4 in the Ubuntu setup
  above) — the private key never leaves the phone's secure storage once
  imported.
- This app is intended for personal use on networks/devices you control;
  it is not hardened for public app-store distribution.
